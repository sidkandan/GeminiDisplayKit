# Runbook — Hosting a `gdk` game from a MacBook Pro

> Generalized from `PULSEBLADE_MACBOOK_PRO_RUNBOOK.md` (authored today
> on the Mac mini for a specific demo scenario). This version applies
> to **any** game built with Gemini Display Kit.

**Use case:** You're demoing on stage and your primary host machine (Mac mini, desktop server, etc.) might sleep — or you want to run the demo entirely from your laptop. This runbook walks through hosting the bridge + tunnel from a MacBook Pro.

## The chain

```
Meta Ray-Ban Display Web App
  ↓ (public HTTPS URL — stays the same across glasses sessions)
Cloudflare quick-tunnel on MacBook Pro
  ↓
gdk bridge on 127.0.0.1:8787
  ↓
Gemini API (Flash / Nano Banana / Veo / Lyria / Managed Agents)
```

If any link breaks, the HUD shows the cached shell but generation calls fail.

## One-time setup

```bash
# 1. Clone the repo
git clone https://github.com/sidkandan/GeminiDisplayKit
cd GeminiDisplayKit

# 2. Install host tools (macOS)
brew install node cloudflared android-platform-tools

# Verify
node --version            # >= 18
cloudflared --version
adb version               # optional — only needed for glasses doctor / capture

# 3. Install framework deps
npm install

# 4. Pick an example + set up its env
cd examples/omni-odyssey   # or examples/pulseblade
cp .env.example .env
chmod 600 .env
nano .env                   # set GEMINI_API_KEY

# 5. Install example deps
npm install
```

## Start the bridge + tunnel

`gdk dev` does all three steps in one command (bridge, tunnel, QR):

```bash
cd examples/omni-odyssey
caffeinate -dimsu npx gdk dev
```

`caffeinate -dimsu` keeps the MacBook Pro awake while `gdk dev` is running. Without it, lid-close or idle will sleep the laptop and kill the tunnel.

Expected output:

```
[bridge]    http://127.0.0.1:8787/
[display]   ./display
[routes]    GET /scene-data, GET /scene-image, POST /choose, GET /conjure, ...
[tunnel]    https://random-words.trycloudflare.com
[deeplink]  fb-viewapp://web_app_deep_link?appName=OmniOdyssey&appUrl=...
[qr]        saved to artifacts/install-qr.png

████ ███ ██ █████ ████ ...
```

Copy the `trycloudflare.com` URL — you'll need it for the deeplink + QR.

## Stage the Web App on the glasses

Meta Display Web Apps require public HTTPS. Do not use `localhost`, LAN IP, or the MacBook hostname as the app URL.

### Option A — ADB deeplink (fastest)

Connect the Pixel and verify:

```bash
adb devices -l
# Expected: <YOUR_SERIAL>    device
```

Generate + open the deeplink:

```bash
export PUBLIC_URL="https://your-tunnel.trycloudflare.com"
PAYLOAD=$(node bin/gdk.mjs deploy --url "$PUBLIC_URL" --name OmniOdyssey 2>&1 | grep '^\[deeplink\]' | sed 's/^\[deeplink\]  //')
adb shell "am start -W -a android.intent.action.VIEW -d '$PAYLOAD'"
```

The Pixel shows the Meta AI "Add Web App" sheet → tap **Connect**.

> "Connect" stages the app in the Display launcher. It does not auto-open it on the glasses.

### Option B — QR (no ADB)

```bash
open artifacts/install-qr.png    # already generated by `gdk dev`
```

Scan with the Pixel camera → Meta AI → Add Web App → Connect.

## Launch on the glasses

Only after staging:

1. Put on the glasses
2. Open the app launcher (look up + swipe)
3. Choose your app
4. Use Neural Band — arrows + pinch

If you're only preparing for a demo and don't want to launch yet, stop after the Pixel shows the app connected.

## Demo-day preflight

Run before the slot:

```bash
cd <your repo root>
bash scripts/demo-day.sh
```

That checks: Node version, cloudflared availability, `.env` files, the captured prompt-arena traces, optional pre-warmed assets, etc.

For more aggressive verification:

```bash
node --check bin/gdk.mjs
node --check src/bridge/server.mjs
npm test
curl -sS "$PUBLIC_URL" | head -5         # confirm the tunnel serves the HUD
curl -sS "$PUBLIC_URL/scene-data" | jq .  # confirm dynamic routes work through the tunnel
```

## Sleep / power settings

For the demo:

- Plug the MacBook Pro into power
- Disable Low Power Mode
- Keep the lid open (or verify clamshell-mode + external display first)
- Avoid Wi-Fi network switching after staging the Web App
- Keep `caffeinate -dimsu` running for the duration

## Common failures

### "The cloudflared URL changed"

Quick tunnels rotate when restarted. If the HUD goes blank:

1. Restart `gdk dev` (it'll print a new URL)
2. Re-mint the deeplink: `gdk deploy --url "$NEW_URL" --name OmniOdyssey`
3. Re-scan the new QR on the Pixel
4. Tap **Connect** again

### "Port 8787 is busy"

```bash
lsof -nP -iTCP:8787 -sTCP:LISTEN
# Kill the stale process or change PORT in .env
```

### "Pixel doesn't show up in adb"

```bash
adb kill-server && adb start-server && adb devices -l
```

USB unreliable? Use the QR flow — ADB is not required after the app is connected.

### "Glasses load an old cached version of the game"

Bust the cache by appending a query string when staging:

```bash
gdk deploy --url "$PUBLIC_URL/?v=2" --name OmniOdyssey
```

Then re-scan and re-connect.

### "Gemini key problems"

If the HUD renders but generation fails:

- Confirm `.env` exists in your example dir (`examples/<game>/.env`)
- Confirm `GEMINI_API_KEY` is set and valid
- Restart `gdk dev` after editing `.env`

Do **not** paste the key into browser code, the public repo, or any committed file.

## Known boundaries

- Meta Display Web Apps do not get camera or microphone access. Live capture needs the separate Pixel/DAT/native bridge lane.
- The PulseBlade rhythm game's pose tracking uses the page's `deviceorientation` API — only works when the user grants motion permission on the Pixel.
- `caffeinate` prevents sleep *while it is running* — it does not make a closed, unplugged MacBook a server.
- Cloudflare quick tunnels are temporary and rotate. For a stable URL, use a paid named tunnel or any Node-hosting platform with `gdk deploy`.

## Clean shutdown

`Ctrl+C` in the `gdk dev` terminal. If you used `tmux`:

```bash
tmux kill-session -t gdk
```

The Web App may remain listed in the glasses launcher, but it won't work until you bring up a live public URL again.
